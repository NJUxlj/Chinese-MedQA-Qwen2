# 医疗多智能体会诊系统 Gradio UI

本目录包含医疗多智能体会诊系统的用户界面，基于 Gradio 框架实现。界面提供了直观的可视化操作方式，使用户能够方便地与后端 mdagents 医疗多智能体系统进行交互。

## 项目概述

医疗多智能体会诊系统是一个基于人工智能技术的医疗诊断辅助平台，通过多个专业智能体的协同工作，为用户提供全面的医疗分析和建议。该系统整合了初级诊疗医生、专科医生、协调员、招募者、审查员和整合者等多种角色，形成了一个完整的多学科会诊工作流程。Gradio UI 作为系统的可视化前端，提供了简洁明了的操作界面，使用户无需了解底层技术细节即可使用系统的全部功能。

界面设计遵循了现代 Web 应用的最佳实践，采用响应式布局确保在不同设备上都能获得良好的使用体验。配色方案选用了医疗领域常用的蓝色系主色调，配合绿色表示正常状态、黄色表示警告、红色表示紧急，整体视觉风格专业且易于理解。界面支持中英文双语显示，所有标签和提示信息均采用中文，提升了国内医疗工作者的使用便利性。

## 功能特性

### 智能会诊功能

智能会诊是本系统的核心功能，用户可以通过输入患者症状描述和基本信息，获取由多个智能体协同分析得出的诊断建议和治疗方案。会诊流程首先对输入的医疗查询进行复杂度分析，根据分析结果决定需要参与的智能体类型和数量。简单病例可能只需要初级诊疗医生单独处理，而复杂病例则会启动完整的多学科会诊流程，由多个专业智能体分别提供意见，最终通过共识机制形成综合诊断结果。

界面左侧提供输入区域，用户可以填写症状描述文本、患者年龄、性别和既往病史等关键信息。症状描述支持详细的文本输入，系统会自动分析其中的医疗术语、症状数量和涉及的专业领域。右侧则以选项卡形式展示不同类型的分析结果，包括复杂度分析、协作策略、智能体分析、共识结果和最终报告，用户可以根据需要切换查看各个详细结果。所有结果都采用结构化的 Markdown 格式呈现，便于阅读和理解。

### 快速分析功能

快速分析功能提供了轻量级的复杂度评估能力，用户无需输入完整的患者信息即可快速了解某个医疗查询的复杂程度。这一功能特别适合在正式会诊前进行初步筛选，或者用于学习不同类型病例的复杂度特点。快速分析会返回查询的复杂度等级、详细特征分析以及推荐的智能体类型，帮助用户理解系统如何评估医疗问题的复杂程度。

### 系统状态监控

系统状态页面实时展示医疗多智能体系统的运行状况，包括在线状态、智能体总数、活跃智能体数量、总会诊次数、共识成功率等关键指标。通过这些信息，管理员和用户可以了解系统的负载情况和性能表现。状态监控功能还提供了刷新按钮，用户可以手动触发状态更新，获取最新的系统运行数据。

### 示例查询

界面内置了四个典型医疗场景的示例查询，涵盖简单感冒咨询、慢性病管理、复杂多学科会诊和术后康复咨询等不同类型。用户可以通过点击示例按钮快速加载预设的查询内容，了解系统的使用方法。这些示例经过精心设计，能够展示系统在不同复杂度等级下的处理能力和结果展示方式。

## 界面布局

### 主界面结构

Gradio UI 的主界面采用顶部标题区加选项卡内容区的经典布局。顶部标题区包含系统名称和简短描述，采用渐变色背景突出显示，具有良好的视觉引导作用。选项卡区域分为五个主要标签页，分别是智能会诊、快速分析、系统状态、使用说明和免责声明。每个标签页对应不同的功能模块，用户通过点击标签即可切换到相应功能。

智能会诊标签页采用左右两栏布局，左侧为输入区域，右侧为结果展示区域。这种布局方式充分利用了屏幕空间，使用户能够在输入信息的同时观察结果变化。输入区域包含症状描述文本框、患者信息表单和高级选项折叠面板，布局紧凑但功能完整。结果展示区域采用内嵌选项卡设计，将复杂度分析、协作策略、智能体分析、共识结果和最终报告分别展示，用户可以通过点击不同选项卡查看相应内容。

### 响应式设计

界面支持响应式布局，能够根据浏览器窗口大小自动调整组件排列方式。在宽屏显示器上，输入区域和结果区域并排显示，充分利用大屏幕优势。在窄屏设备上，两者会自动上下堆叠，确保所有功能可用。界面最大宽度限制为 1600 像素，超大屏幕上不会出现过度拉伸的问题，保证阅读体验的一致性。

### 状态指示

界面使用颜色和图标来直观表示各种状态信息。复杂度等级使用绿色圆点表示简单、黄色圆点表示中等、红色圆点表示复杂，一目了然。智能体处理状态使用对勾表示完成、旋转图标表示处理中、时钟图标表示等待中、叉号表示错误。共识水平使用进度条形式的字符画展示，既美观又节省空间。系统状态页面使用绿色表示在线、红色表示离线，通过颜色快速传递系统运行状况。

## 使用方法

### 启动界面

在确保后端 API 服务已启动的情况下，运行以下命令启动 Gradio UI 界面：

```bash
cd /Users/xiniuyiliao/Desktop/code/Chinese-MedQA-Qwen2
python -m src.ui.medagents_ui
```

界面启动后会显示本地访问地址，通常为 http://localhost:7860。在浏览器中打开该地址即可使用界面。如果需要在局域网内共享访问，可以使用 0.0.0.0 作为服务器地址。

### 进行智能会诊

进行智能会诊的完整流程如下：首先在症状描述文本框中详细输入患者的症状表现，包括主要症状、伴随症状、症状持续时间和加重缓解因素等信息。描述越详细，系统的分析结果越准确。然后在患者信息区域填写患者的年龄、性别和既往病史。既往病史可以用逗号分隔多个疾病名称，如高血压、糖尿病、冠心病。如果有特殊的过敏史或用药史，也可以在症状描述中一并说明。

填写完成后，点击"开始会诊"按钮提交查询。系统会自动进行复杂度分析、分配协作策略、调用相关智能体进行分析、形成共识并生成最终报告。整个过程可能需要数秒到数十秒不等，取决于查询的复杂程度。结果会实时显示在右侧的结果区域，用户可以切换不同选项卡查看各类详细信息。处理时间会显示在界面底部，帮助用户了解系统响应速度。

### 使用示例查询

如果初次使用或不熟悉系统操作，可以点击界面下方的示例按钮加载预设查询。系统提供了四个典型场景的示例，每个示例都包含完整的症状描述和患者信息。点击示例按钮后，输入区域会自动填充相应内容，用户可以直接点击"开始会诊"查看处理结果。通过这种方式，用户可以快速了解系统的功能特点和结果展示方式。

### 查看系统状态

系统状态页面提供了后端服务的运行监控信息。点击"刷新状态"按钮可以获取最新的状态数据，包括当前在线的智能体数量、总会诊次数和共识成功率等指标。如果发现系统负载过高或共识成功率下降，可能需要检查后端服务运行状况或考虑增加系统资源。

## API 接口

### 查询接口

完整会诊功能通过 `/api/mdagents/query` 接口实现，请求参数包含 query（必填的症状描述文本）、patient_context（可选的患者背景信息字典，包含 age、gender、history 等字段）和 options（可选的配置选项）。响应结果包含 session_id（会话标识符）、complexity_analysis（复杂度分析结果）、collaboration_strategy（协作策略）、agent_results（各智能体分析结果）、consensus_result（共识结果）、final_report（最终报告）、processing_time（处理时间）和 timestamp（时间戳）。

复杂度分析接口通过 `/api/mdagents/complexity/analyze` 实现，用于单独分析查询的复杂度等级。请求参数包含 query（待分析的医疗查询文本）和 include_features（是否返回详细特征布尔值）。响应结果包含查询文本、复杂度分数、复杂度等级、详细特征对象、分析置信度和推荐智能体列表。

### 配置选项

在提交会诊查询时，可以通过 options 参数进行以下配置：show_steps 控制是否显示处理步骤的详细信息，设为 true 时返回结果会包含更详细的处理过程信息。这些选项通过高级选项折叠面板中的复选框进行设置，用户可以根据需要开启或关闭相应功能。

## 示例查询说明

### 简单感冒咨询示例

该示例展示了系统如何处理简单的上呼吸道感染病例。患者表现为发热、咳嗽、流鼻涕等症状，病程两天，体温最高 38.5°C，年龄 35 岁男性。系统会判定为简单复杂度，可能只需要初级诊疗医生进行初步分析和常规处理。输出结果会包含基础诊断建议和日常护理注意事项。

### 慢性病管理示例

该示例展示了系统处理多慢性病叠加的典型场景。患者为 65 岁男性，有高血压和糖尿病史，近期出现胸痛和呼吸困难。这类病例涉及心血管和呼吸两个专科，需要综合考虑慢性病管理方案。系统会判定为中等或复杂复杂度，启动多个智能体协同分析，给出心血管疾病相关的诊断建议和治疗方案。

### 复杂多学科会诊示例

该示例展示了系统处理复杂多学科病例的能力。患者为 58 岁女性，有冠心病、糖尿病、慢性肾病史，近期出现下肢水肿和夜间呼吸困难，心电图和肾功能检查都有异常发现。这类病例需要心脏内科、内分泌科和肾内科等多个专科协同分析。系统会判定为复杂复杂度，启动完整的多学科会诊流程，最终形成综合性的诊断和治疗建议。

### 术后康复咨询示例

该示例展示了系统处理术后并发症的能力。患者三天前进行腹腔镜胆囊切除手术，术后情况良好，但今天出现发热和腹痛加剧，白细胞升高。这类病例需要考虑术后感染、胆漏等可能的并发症。系统会综合分析手术史和当前症状，给出相应的处理建议。

## 注意事项

### 免责声明

本系统仅供参考，不能替代专业医疗诊断。系统输出的分析结果和建议仅供参考信息，不构成医学诊断或治疗建议。用户应始终以专业医生的诊断和治疗为准，切勿仅凭本系统的输出结果进行自我诊断或治疗决策。对于紧急病情，应立即就医或拨打急救电话。

### 数据安全

用户在使用本系统时输入的症状描述和患者信息会传输到后端服务进行处理。系统会记录这些信息以生成会诊报告，但不会将这些信息用于其他目的。建议用户在使用时避免输入真实的患者身份信息，以保护患者隐私。

### 系统局限

当前版本系统存在以下局限性：复杂度分析主要基于关键词匹配，对于表述特殊的病例可能分析不准确；智能体知识库基于训练数据，可能存在知识盲区；共识机制采用规则化方法，在极端情况下可能无法形成有效共识。系统会持续更新改进，提升分析准确性和可靠性。

### 技术支持

如在使用过程中遇到问题，请检查后端 API 服务是否正常运行，确认网络连接正常。如果问题持续存在，可以查看后端日志获取更详细的错误信息。系统版本和 API 接口定义请参考相关技术文档。
